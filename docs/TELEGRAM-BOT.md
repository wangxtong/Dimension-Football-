# 维度足球 Telegram 功能与验收

机器人为 `@LYZKYPbot`，沿用主项目已授权群的目标指纹 `c061d82bf8f5ff23`。它与现有 `@WDZQYCbot` 消息桥是不同服务，本次不更换旧桥的 Webhook、目标或凭据。

## 两种交付分别验收

1. **每日赛事与数据状态**：北京时间每日 09:00 后首个符合新鲜性要求、完成网站同版本回读的观察轮次触发。包含未来 24 小时赛程、来源覆盖、真实取得与到期时间、缺项和看板入口。GitHub 触发可能延迟，不能保证 09:00 准点。
2. **正式预测日报**：当前仍为 `RELEASE_GATE=BLOCKED`。状态日报、历史回测或按钮能用，均不代表正式预测已发布或商业验收通过。

新日报使用独立的 R2 日锁和回执，不修改正式预测的通知回执。锁按北京时间日期及固定目标生成，不能因新 reportId 或 runner 重启重复发送。已接收、发送结果未知、未完成锁都不盲目重发；Telegram 接收回执不代表用户已读。

## Bot 内分类按钮

| 按钮 | 输出与实际用途 |
| --- | --- |
| ⚽ 今日赛事 | 当前采集的赛程、中文球队、北京时间，分页及刷新；标明公开样本和数据时效 |
| ⭐ 优选门槛 | 模型发布状态、有效来源和真实初盘缺项；没有合格优选时直接说明，不凑场次 |
| 📚 历史回测 | 已冻结历史报告中的分联赛指标、样本量及提前量；不冒充当前前瞻表现 |
| 📊 模型状态 | 已保存实验的基线比较及是否采用；不把未采用模型写成准确率提升 |
| 🧾 赛后核账 | 当前公开核账能力与证据边界；隔离实验的两场核账不能写成生产成绩 |
| 📡 来源诊断 | 各源有效覆盖、双源对齐、报价取得／到期及缺项；“接口成功”不等于有合格数据 |
| 🔎 发布排查 | 网站、独立状态日报和正式预测分别呈现，提供实际报告标识、消息回执与下一步 |

支持 `/start`、`/menu`、`/help`、`/status`。分类按钮在机器人消息中切换内容；保留“返回菜单”“刷新”和必要分页，网页入口仍指向原域名及原登录页。实时用户点击成功必须单独核验，不能拿 URL 能打开或离线模拟当作真实回调验收。

## 配置与权限

Sites 秘密配置名为 `TELEGRAM_BOT_TOKEN`、`TELEGRAM_CHAT_ID`、`TELEGRAM_WEBHOOK_SECRET`。通过原生 Sites 秘密管理保存，并随已保存网站版本部署生效；不写进源码、构建包、日志或 GitHub 工作流正文。GitHub Secrets、Sites 秘密和 ECS 的 `/etc/vantis/collector.env` 是不同运行环境，任何一处有配置都不能证明其他环境已绑定。

`POST /internal/observation-notifications` 只接受 `reportId`，使用既有固定仓库／main／工作流／受众的 GitHub OIDC 身份。Site 从当前已核验的观察包重新生成文本，拒绝模拟数据、预测内容、过期观察和错误目标；访客 Cookie 不能调用此写入入口。

`POST /telegram/webhook` 使用独立 Telegram Webhook 密钥校验，限定当前机器人和原群，回调数据执行白名单；不执行任意命令或接收任意目的地。R2 按 update_id 防重复；旧的命令消息不在恢复接入时批量补发。首次注册 Webhook 前须读取现配置，存在其他消费者时不能直接覆盖。

`GET /api/observation-notifications` 在网站登录后返回独立日报的脱敏状态，不返回令牌、群 ID、原始 Telegram 响应或用户消息。

## 上线验收清单

- 同一候选完整回归、固定输入回测、浏览器与部署包检查通过，必测零跳过；审查 CI 日志。
- Sites 部署记录绑定源码提交和环境修订；群身份与机器人权限实际核对。
- Telegram Webhook 地址、允许更新类型和群命令菜单实际回读。
- 新一轮采集与网站 reportId／摘要一致；日报取得真实消息 ID、目标指纹和持久回执。
- 第二次调用确认没有新增消息；未知结果不自动重发。
- 七类按钮、刷新与分页经真实用户点击后核对 Webhook 处理结果；此前只能记录代码或模拟测试通过。
- 正式预测门禁保持阻断；阿里云部署须另取现场运行版本、配置和持久化证据。

任何一项未验证均单列为未完成，不以局部 CI、配置写入或页面可读宣称生产交付完成。
