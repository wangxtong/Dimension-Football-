# 信息源自动维护

本功能围绕现有官方赛程接口建立自动更新、失败冷却和备用切换。每轮读取最新配置与健康记录，取得新赛程后继续现有预测分析。它不发现任意网站、不自动修改接口 URL，也不把未接通的注册项当成可用来源。

## 能力边界

| 数据能力 | 自动管理 | 替换条件 |
| --- | --- | --- |
| 五大联赛赛前赛程 | football-data.org 与 API-Football，固定官方主机 | 两家凭据均配置且备用通过格式、身份、时效和覆盖检查 |
| API-Football 深度分析的赛程输入 | 健康检查与冷却；固定 API-Football | 不能用 `fd-*` 代替 `af-*`；其伤停、首发、历史、预测、赔率端点仍采用原有逐请求诊断，本版不为这些端点建立独立熔断 |
| Titan007 亚洲盘 | 每轮现有采集 + 报告健康摘要 | 尚无已实现的独立同类备用；M88、12Bet、SBOBET 始终只算一组 |
| Statarea 1X2 辅助信号 | 每轮现有采集 + 报告健康摘要 | 无已验证的自动备用，不转换成亚洲盘概率 |
| 天天盈球 | 仅监测现有免费列表 | 不产生预测票，不替代 Statarea |
| 其他未实现/受限来源 | 保留原有缺失诊断 | 不请求、不自动启用 |

公开证据源的摘要来自本轮真实采集诊断；无合适比赛、未触发采集时为 `not_checked`。两家官方赛程的切换由本模块负责；公开网页另由[爬虫模块](CRAWLER_INTEGRATION.md)执行域名限速、访问挑战识别和持久冷却。它们不能替代尚未接通的盘口、伤停或首发来源。某次网络失败只说明当前执行环境中的请求失败，不证明上游全球故障。

## 选择与恢复流程

1. 无真实凭据时直接失败；手工输入文件和 demo 保持原有独立路径。
2. 按优先级检查已配置的源。未配置的源不请求，处于冷却期的源跳过。
3. 每家最多获取五个联赛一次。沿用适配器的 6 秒请求上限、2 MB 响应限制、禁止重定向、严格赛事身份、分页及 HTTP 时间戳检查，并服从整轮预算与取消信号。
4. 五个联赛均完整即停止，不请求备用。新鲜、结构合法的空结果也属于完整。
5. 不完整时尝试一次备用。按完整联赛数优先、其次部分可用联赛数比较，平手保留先尝试的源；保留胜出源的一整个池，不按比赛数量猜覆盖率、不跨源合并赛事 ID。全失败返回空池及非零退出码，不重用过期赛程充当当前结果。
6. 记录本轮尝试、延迟、逐联赛状态、失败分类与选用源。不同源的原始身份和时间字段保留在赛程中；原检查点不会把旧身份证据移接到新身份。
7. 普通全源失败连续两轮进入冷却，之后指数延长。冷却到期后的下一轮按优先级探测，成功即清零失败计数并恢复使用。单个联赛权限不足不会禁止其余四个联赛；限流或配额错误可能对整个服务生效。

主源部分可用而备用更差时，继续输出主源已取得的比赛，`poolComplete=false`。恢复备用成功时，完整性按被选中的来源计算；主源故障仍在 `sourceManagement.attempts` 中可见。取消或耗尽本地预算会停止继续切换，不将本次中断记录为供应商故障。

## 配置与频率

默认文件为 `config/sources.json`，可用 `--sources-config FILE` 指定受管理的本地文件：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `fixturePriority` | `["football-data.org", "api-football"]` | 基础采集优先级；可反转，或只列一家以关闭备用 |
| `failureThreshold` | `2` | 普通全源失败连续轮数，范围 1–10 |
| `cooldownMs` | `300000` | 达到阈值后的首次普通故障冷却，5 分钟 |
| `maxCooldownMs` | `3600000` | 普通故障指数冷却上限，1 小时 |
| `authCooldownMs` | `21600000` | 全源 401/403 或套餐受限后的冷却，6 小时 |
| `quotaCooldownMs` | `86400000` | API 明确报告配额耗尽后的冷却，24 小时 |

时间配置必须为 1 分钟至 24 小时的整数毫秒值。429 至少冷却 1 分钟；`Retry-After` 支持秒数与 HTTP 日期，取不早于本地策略的时间，最多信任 24 小时。它是重试许可时间，不保证该时刻账户已恢复配额。未识别的字段、URL、自定义主机和未实现来源 ID 均拒绝，避免凭据被路由到陌生接口。

默认 ECS / Actions 仍每小时采集，冷却到期后等下一轮执行；本功能不启动额外守护进程或分钟调度。健康检测使用实际采集响应，不另外发送心跳；正常基础赛程 5 次请求，切换最多共 10 次。深度分析的至多 250 次请求另算，不能通过提高调度频率忽略套餐额度。由于某一家仍将五个联赛并发请求，本轮发现 429 时，其余同轮请求可能已经发出；冷却保护后续轮次。

显式 `--deep-analysis` 或仅配置 API-Football 自动深度分析时，赛程源固定为 API-Football；配置若禁用该源会直接报错。基础模式切换至 API-Football 不会额外启用付费深度请求。深度材料缺失仍按原有诊断展示，本次不宣称修复既有审计的深度退出码或全周期锁问题。

## 状态、报告与恢复

默认健康文件为 `.collection-state/state.json.sources.json`；指定 `--state /var/lib/vantis/state.json` 后对应 `/var/lib/vantis/state.json.sources.json`。内容仅包含枚举来源、健康状态、完整联赛数、连续失败数、检查时间、完整成功时间、下次探测时间和最近 50 次来源变更。通过独占锁与原子写入防止并发丢失健康更新；锁只覆盖这次来源获取和状态写入，不代表已覆盖既有系统的整个深度发布周期。

```sh
# 只读查看历史健康状态、记录年龄和是否尚处于冷却期
npm run sources:status -- --state /var/lib/vantis/state.json

# 正式采集，沿用已有凭据文件
node --env-file=/etc/vantis/collector.env collector/run.mjs --state /var/lib/vantis/state.json --out /var/lib/vantis/reports
```

健康状态中的 `healthy` 指最近一次已完成检查，需结合 `lastCheckedAt` / `observationAgeMs` 判断历史年龄；离线查看不会刷新它。报告 JSON 增加 `sourceManagement`，消息版增加来源维护表；历史未请求源不应当作当前可用。保留原有逐场证据和时效门槛，状态中没有请求头、密钥、原始响应或异常文本。

缺失健康文件从空状态开始；损坏或结构不合法时明确失败，避免悄悄清空配额冷却。更换凭据不会主动绕过已保存冷却；等待后续到期轮次，或在停止调度并核实配额后，由运维备份并处理该专用状态。不要为了恢复接口删除正式比赛检查点。

正常结束释放健康锁。强制终止后，确认没有采集进程，按现有恢复工具处理健康锁：

```sh
node collector/recover-lock.mjs --state /var/lib/vantis/state.json.sources.json
```

恢复工具仍检查本机进程身份，不删除活锁。Actions 缓存比赛检查点、官方源健康和公开爬虫三份 JSON，不缓存锁；缓存前缀为 `collection-v3`。缓存丢失会失去冷却历史，所以生产持久状态仍应放在服务器磁盘并备份。

## 增加新的备用接口

新增源需要先实现并验证适配器，再登记到允许列表。配置只能切换已实现的接口：

1. 确认授权、费用、速率、覆盖联赛、数据更新周期和实际可用字段。
2. 固定官方域名、认证头、超时、分页与响应上限，禁止重定向转发凭据。
3. 建立赛程、球队、比赛时段和市场的明确映射；相同能力才能互为备用，跨服务 ID 必须有独立核验。
4. 验证 401/403/429/5xx、过期数据、结构变化、合法空结果、分页缺失、取消和断网，并以真实授权样本验证字段。
5. 若为盘口来源，记录真实采集/内容渠道的独立组；不同博彩公司或同站镜像不增加独立证据数。

本次已建立两家官方赛程间的替换能力。第二个独立盘口源、伤停/首发专用备用源、分钟级调度与跨供应商统一赛事身份仍是后续接入工作。
