# 历史评估质量诊断

`node collector/evaluation-quality.mjs --reports /path/to/reports` 只读输出独立 JSON，不改历史资产、预测、模型参数或发布门槛。`readEvaluationQuality({directory, nowISO})` 先复用已有历史证据校验，确认 reportId、代码版本、manifest、输入哈希、逐场结果及聚合指标吻合，再运行诊断。它不拟合校准器，也不挑选最好的提前量；`releaseGate` 始终 `BLOCKED`。

`calibrationDiagnostics(rows)` 使用预先固定的5个等宽区间，分别统计主胜、平局、客胜的样本数、平均预测概率、真实发生频率和差值。每类 ECE 是各区间绝对差按样本占比加权的均值，`macroECE` 是三类 ECE 的平均值。没有样本时为 null；不足20场的区间标记不足。ECE依赖分箱且存在有限样本偏差，低ECE或当前样本恰好吻合都不代表已校准。

`evaluateQualityGroups(groups)` 在同一组内拒绝重复比赛、跨来源或混提前量记录。模型和基准必须是同场配对。置信区间按 UTC 周一开始的比赛周分块，完整保留该周所有比赛及每场双方评分，固定种子抽样2000次，输出配对 Brier 差、Log loss 差及模型 macroECE 的百分位近似95%区间。差值始终是模型减基准，损失指标负值较好。每次抽到的周场数可能不同，均值按比赛总数计算。少于8个实际观察周时不提供区间；8–19周明确标记 `few-temporal-blocks`。这些数量仅为诊断规则，不是新的发布门槛。

按周抽样只处理同周依赖，仍假设周与周独立。球队跨周相关、跨赛季变化、历史修订、有限区间数及多个提前量比较均可能影响推断；分块区间不保证比按场区间更宽。报告披露周样本数、赛季分布和时间范围。不能因为区间未跨零就声称已通过商业验收。

跨提前量按同源赛事ID识别重复出现，输出总出现次数、唯一比赛数及组间重叠；不合并准确率，不把重复出现当作额外样本。不同来源仍没有经过审核的跨源身份映射，不能假定为不同比赛。提前量之间样本集合不同也不能直接解释成模型改善。

此报告描述当前修订历史快照，既不是严格前瞻，也不是未来胜率或收益预测。原始训练可见性、冻结基准、独立前瞻样本和正式概率校准证据仍未完成；这里没有重复用同一测试集调参或新增预测能力。
