# 无需手工服务器安装的自动供数

现有工具可以管理 GitHub 和 Sites，但没有阿里云命令身份。生产恢复先使用原方案中的 GitHub Actions 短期 OIDC 身份和 Sites 持久存储，不把 ECS 健康接口当成安装授权。

## 身份与数据

固定接受本私有仓库 ID、所有者 ID、main 分支、`live-publication.yml` 工作流和本站受众的 GitHub OIDC JWT。验证发行方、签名、公钥、签发与到期时间；访客登录 Cookie 不授予机器写入权限。机器令牌只保留在请求过程中，不写入状态、代码或日志。

精简网站报告及其公开原始输入在私有 R2 中按 reportId 不可变保存；校验完整结构、摘要、大小和时效后才条件切换当前版本。回执与报告 ID 绑定。网页每分钟检查新报告，报告仍以真实采集时间判断有效期。

状态在 R2 中按版本条件更新。runner 只恢复白名单内的采集状态、当前报告、回放输入和预测结果账本；锁文件、环境配置、符号链接和秘密不进入检查点。版本冲突停止执行，不能覆盖较新的状态。超出状态容量上限时保留上一成功版本并明确失败，不能静默删掉尚未评分的预测。

## 调度与通知

Actions 每 5 分钟申请运行；GitHub 可能延迟或跳过调度，因此这不是分钟级调度保证。赛程约每 15 分钟更新，赛果约每小时检查，盘口仅在未来 24 小时有目标比赛时采集。所有来源仍遵守原有冷却、请求预算和数据门槛。

发布成功要求网站当前 reportId 与摘要实际回读一致。通知由站点统一发送，使用独立持久 claim 先登记后请求 Telegram；同一目标每 UTC 小时最多一次摘要。网络结果不明确时记为 unknown，不盲目重发。平台接收回执不代表用户已读。

完整逐场回测细节仍包含在本轮 collection 报告中，随工作流附件保留 90 天；它们未全部进入 4 MB 网站包。R2 长期保存精简报告、回放输入和预测账本，不能将附件有限保留期说成永久归档。单份状态最多 32 MiB、10000 个文件；达到上限时停止并告警，下一阶段须按赛事拆分长期归档。

原 `public-sources.yml` 保留灾备职责；自动主通路实际通过验收后再暂停其小时定时执行，手动归档仍可用。ECS 以后接入时必须先验证同版本读回及持久状态迁移，再切换唯一发布者。

## 验收

必须实测工作流运行、R2 恢复与条件更新、生产网站实际读取、通知接收回执和重复调用不重发。不能从保存版本、构建成功或文件上传成功推断这条闭环已接通。已知的第二独立盘口来源及真实初盘缺口继续显示，不以放宽条件产生严格候选。


## R1 当前实施边界

以上身份、状态和版本合同继续使用，正式预测发布已收紧为硬 `BLOCKED`。`POST /internal/publications` 与预测通知接口均拒绝，不能用 JSON GREEN 或环境变量开启。

默认工作流运行 `observations`：每 5 分钟尝试调度，每 15 分钟实际采集公开赛程。`POST /internal/observations` 由服务端按白名单投影，只保留赛程、来源覆盖、原始时间及阻断状态；删除概率、下注方向、候选盘口、回测与原始历史。投影有独立 reportId，并记录 originReportId。上传不等于发布：初始回执未核验，仅机器 GET status 实际同版本回读成功后写 servedVerified。

该模式不生成新的预测、机会或回放账本；已有账本原样持久保留，40 轮模拟状态体积趋稳。长期研究账本的分块归档仍须后续实现，容量工具只诊断和规划，未执行迁移。手动 research 模式保留供独立研究，但所有对外预测出口仍禁发。自动观察工作流不发送 Telegram；中文按钮消息是另行核验的状态通知，不能携带未批准推荐。

网站新版本和观察链路通过验收时，只能记录“实时采集观察可读”，不能将其称为 ECS 已部署、五联赛模型已校准或商业发布完成。
