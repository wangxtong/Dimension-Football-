## 二、我原本想提的「按联赛筛选」，本身就是过拟合

我第一反应是「只推意甲+法甲，命中率立刻到 57.6%」。**这个想法有问题，我先自己否掉**：

```
这是典型的「事后选择」（post-hoc selection）：
看到意甲 59.42% 就挑意甲，看到英超 39.39% 就剔英超，
等于用同一批数据既做发现又做验证。
换一批赛季，意甲可能就掉到 45%，英超可能回到 55%。
```

如果按这个逻辑上线，就是在复制我们批评过的「选择性展示」。所以我**不打算**直接按联赛筛。

## 三、我认为真正需要先回答的三个问题

**Q1：英超 39.39% 是模型问题还是样本波动？**
- 66 场，标准误约 sqrt(0.5*0.5/66) = 6.2%
- 39.39% 距 50% 有 1.7 个标准误，**不足以单独判定模型失效**
- 但 Brier 0.6485 也明显高于其他联赛（0.585-0.597），两个指标同向，**不能全归因于波动**
- 需要的手段：分赛季看 PL 的 accuracy 序列，如果每个赛季都低 → 模型问题；如果只有某个赛季低 → 样本问题

**Q2：联赛间差异是真实的还是配置问题？**
- `venue-poisson-v2` 对每个联赛用同一套 `lookbackDays: 540 / halfLifeDays: 180 / priorMatches: 6`
- 英超的比赛密度、强度、平局率与意甲不同，**固定超参可能对某些联赛系统性偏差**
- 需要验证：对每个联赛单独做超参敏感性分析，看最优值是否显著不同

**Q3：如果不许事后挑联赛，怎么做才不算作弊？**
我想到三条，请你判断哪条可接受：

| 方案 | 做法 | 防作弊机制 |
| --- | --- | --- |
| **A. 事前分层**（我倾向） | 在**新的前瞻周期开始前**，用历史数据定好「哪些联赛进入推送」，写下规则并冻结；之后按规则执行，不允许中途改 | 规则文件带 commit 时间戳，先于样本产生 |
