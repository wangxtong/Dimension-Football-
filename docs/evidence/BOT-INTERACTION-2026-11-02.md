- 修复前：主项目七按钮均为网页 URL，没有 Bot 内 callback 处理器。现有另一机器人消息桥不在本变更范围。

## 已实现

- 独立 `telegram-bot.mjs`：`/start`、`/menu`、`/help`、`/status`；七类原生按钮为今日赛事、优选门槛、历史回测、模型状态、赛后核账、来源诊断、发布排查。
- 每页带中文分类、表情、北京时间、报告短 ID、分页、刷新、返回主菜单与原看板链接。严格 HTML 转义、UTF-16 长度上限和有界分页。
- `POST /telegram/webhook` 的处理器使用独立密钥头、固定 Bot 身份和原目标群指纹，不接受网页登录 Cookie 代替 Telegram 身份，不向陌生私聊返回报告。
- 普通历史命令超过 10 分钟跳过；旧菜单上的新 callback 可正常刷新，不用菜单消息日期误判点击过期。
- callback 先 `answerCallbackQuery`，再编辑原消息；两步结果分别记录。API 结果未知、原 claim 未完成或重复 update 都不自动重发。
- 私有 R2 按 Bot ID / update ID 原子防重，单独最新状态指针用于只读验收。保存时间、分类、报告 ID 和脱敏回执；不保存用户 ID、原群 ID、消息原文或凭据。
- 只显示服务端校验的观察报告及摘要固定的历史资产。过期数据明确过期；资产缺失明确未知。无生产核账账本时不把隔离测试的两场结果算成生产成绩。
- 日报回执独立检查种类、版本、北京时间日期、目标指纹、报告摘要及状态/原因组合。状态日报接收成功不改变正式预测门禁。

## 验证证据

`node --test --test-isolation=none website/test/telegram-bot.test.mjs`：21 通过，0 失败、0 跳过。

回归包括原群授权、秘密不回显、体积限制、固定 Bot 身份、旧命令不补发、旧菜单新点击、未知/重复/并发防重、确认与编辑分开、消息未修改幂等、存储失败不重发、分页/转义、固定资产损坏拒绝、原始报告含概率拒绝及只读脱敏状态。

A8 独立复核发现并推动修复了三项反例：回调确认跨过行情失效时间、网站回读回执摘要不匹配、最坏 HTML 实体扩展导致五行分页超长。现使用实际经过时间在最终编辑前重判时效，完整绑定回读模式及摘要，并在转义前按 Unicode 码点保守限长；每场仍保留在原分页中。日报消费者同时校验状态/原因、日期、平台接收含义及 sentNow 一致性，不把坏档案解释为已送达。

真实报告兼容测试使用 `website/test/fixtures/telegram-bot-production-readback.json`，来自 PR #56 生产采集任务 `41371689657`，源码 `8560f1fd1348ad0fe758cf93f2527f862d812c53`。保留原报告与摘要，仅去除未消费的 `sourceData` 副本；不会修改源时间。固定时点呈现 13 场赛程、澳门覆盖 4 场、双源 2 场；晚于失效时间后明确显示原观察已过期。
